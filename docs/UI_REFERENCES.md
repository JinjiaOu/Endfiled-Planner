# UI 设计参考研究与方向对比

研究日期：2026-10-19（America/New_York）。状态：Phase 1，供确认，尚未实施界面改造。

## 1. 研究方法与证据边界

本次使用联网搜索定位原始作品，并通过真实浏览器打开 Dribbble、Behance 和《明日方舟：终末地》官网，实际查看页面图片。以下三张截图为本次浏览器实拍，保留站点上下文；不是生成图，也不是本 App 的新设计稿。

Apple 部分 HIG 页面在文本读取工具中仅返回 JavaScript 外壳，因此同时参考 Apple 官方 WWDC 的可读取内容。SEELIE 的浏览器访问超时，未取得可核实截图，仅作为功能组织研究候选，不据此评价其实际视觉。一个 Dribbble 能源仪表盘搜索结果实际打开为 404，已排除，不能把搜索摘要当成有效案例。

静态作品只能证明画面表现，不能证明实际触控、动画、无障碍、计算准确性或产品可用性。下文“可借鉴交互”均为对本 App 的设计建议，并非声称已操作这些概念作品。

## 2. 实际查看的参考案例

### R1 · Dribbble：Dark UI and minimal wellness mobile app

- 作者：Marek Erben。
- [作品原页](https://dribbble.com/shots/21184159-Dark-UI-and-minimal-wellness-mobile-app)。
- [本次截图](ui-audit/references/dribbble-dark-mobile.jpg)。
- 已查看：首张作品中的深色首页和 Journal 列表；没有登录，也没有测试其产品功能。

![Dribbble 深色移动界面，页面实拍](ui-audit/references/dribbble-dark-mobile.jpg)

| 维度 | 画面观察 | 对本 App 的转化 |
|---|---|---|
| 布局 | 清晰的区块标题；右侧 Journal 用对齐的行和细分隔线表达记录，没有给每一行套厚卡片 | 蓝图列表、产能明细采用紧凑行；卡片用于区分任务区域 |
| 配色 | 接近黑色的底、较亮表面、白色主字，强调色很少 | 用表面层次区分画布、面板、弹层；避免每个模块都用高饱和大色块 |
| 字体 | 无衬线标题明显大于辅助信息；长文和时间信息弱化 | 中文使用系统字体，数字对齐；不要让英文装饰标签抢过中文用途 |
| 组件 | 图像入口与纯文本列表并存，操作按钮与正文有明确对比 | 首页使用紧凑任务入口，复杂统计使用列表而非营销式大图 |
| 交互启发 | 画面有明确的 Add session 主操作、列表更多入口 | 一个区域有一个主操作；次要动作可用菜单，但常用画布工具不藏进菜单 |

值得借鉴：层级明确、列表阅读节奏平稳、深色背景不依赖霓虹光效。**不直接采用**：大面积生活方式图片、为氛围预留的空白、图中很小且较淡的辅助字。它不是工业规划工具，不能直接迁移信息密度。

### R2 · Behance：Solar Panel & Energy Monitoring App / Hadron Solar

- 作者署名：Fiona Bui、Ihor Yeromich、Anuitex Design（作品页 Multiple Owners）。
- [完整作品](https://www.behance.net/gallery/101613649/Solar-Panel-Energy-Monitoring-App)。
- [页面中能源监控模块链接](https://www.behance.net/gallery/101613649/Solar-Panel-Energy-Monitoring-App/modules/585465903)。
- [本次截图](ui-audit/references/behance-solar.jpg)。
- 已查看：作品顶部的真实手机界面展示；画面为浅色版本。未逐屏检查整套作品，不能据标签断言其深色版本的质量。

![Behance 能源监控作品，页面实拍](ui-audit/references/behance-solar.jpg)

| 维度 | 画面观察 | 对本 App 的转化 |
|---|---|---|
| 布局 | Grid / Solar / House / Battery 图标分组，时间区间切换，关键数值与图形处于同一阅读区域 | 统计将电力、产出、异常明确分区，让读者先知道当前对象和单位 |
| 配色 | 白与淡蓝为主，蓝色表达选中，黄绿用于曲线和点状强调 | 只借鉴选中态与数据层次，不把浅色配色机械反转为深色 |
| 字体 | 大数值配合较小单位、说明，标题和标签各有层级 | 数值采用等宽数字；单位和精度集中规范，保留现有数值含义 |
| 组件 | 分组选择、分段控件、图表、底部内容有统一边距 | 两地图可用分段选择；统计摘要与明细使用共同栅格 |
| 交互启发 | 分类及时间范围的可见切换入口 | 本 App 没有历史时序数据，不增加假的日/周/月切换和曲线 |

值得借鉴：用实际指标组织监控页面。**不直接采用**：截图中较淡的细字和线、装饰曲线、大量留白。当前模拟器给的是稳定产能结果，应优先比较“实际 / 需求 / 上限”，不能把稳态结果包装成实时历史监控。

| 交互启发 | 导航显示当前区域，内容模块结构清楚 | 编辑器持续显示当前地图、工具与选中对象，避免用户忘记处于删除或画线模式 |

- [Apple WWDC24 · Get started with Dynamic Type](https://developer.apple.com/videos/play/wwdc2024/10074/)。

HIG 部分正文受动态页面读取限制；官方 WWDC 内容已通过联网文本核实，未声称观看了整段视频或取得视频截图。可确认的原则是用较亮的浮层背景表达深度、优先系统文字样式并随字号调整布局。落实到本项目：导航和选择器使用原生容器；内容面板适当不透明；大字时把并排数据改成纵向，不把所有文字等比例塞进原固定框。

本方案采用 44pt 主要触控目标、正文对比度 4.5:1、大字及关键非文字边界 3:1 作为后续验收目标；这是待测的项目标准，不代表当前界面已经达到。

## 3. 从参考研究得到的设计约束

1. 信息终端感来自对齐、状态语义和操作秩序，不来自 HUD 数量。
2. 页面级强调色统一；建筑分类、固液气线路、运行状态仍保留各自语义，不能统一成黄色。
3. 首页、蓝图列表、设置不需要画布网格；网格作为工厂与配方图的工作背景。
4. 数据行优先于大卡片；图表仅在现有数据能真实表达时采用。
5. 屏幕空间优先分给搜索、画布、说明和实际指标；中英文重复标题、ONLINE / READY 这类恒定装饰状态不承担主要信息。
6. 作者署名、版权、免责声明、地图限制、未收敛警告必须保留，不因简洁而删减。

## 4. 三种可实施方向

以下为针对当前功能提出的方案，不是对单一参考作品的复刻。颜色为首轮候选，尚未做最终对比度验收。

| | A · 工业终端（推荐） | B · 原生效率 | C · 数据工作台 |
|---|---|---|---|
| 产品气质 | 终末地设施终端，硬朗、克制 | 熟悉、精致的 iOS 专业工具 | 面向频繁规划的高密度工作环境 |
| 候选背景 / 表面 | `#101318` / `#1A2028` | `#111214` / `#1C1D20` | `#101820` / `#192632` |
| 主强调 / 文字 | 工业黄 `#F2CD45` / `#F2F4F7` | 温和琥珀 `#E7B84A` / 系统主文字 | 冷青 `#67D5DE` / `#EDF4F8`，黄用于重点 |
| 信息结构 | 工作台直达任务；编辑器以画布为主体，工具与属性有明确区域 | 原生 Tab + NavigationStack；搜索、详情、设置遵循系统习惯 | 工厂与统计优先，紧凑摘要、分组数据行和可展开属性 |
| 组件 | 10–14pt 面板圆角、细边界、局部标签 | 系统 List / Form / Sheet、16–20pt 分组表面 | 8–12pt 表面、对齐的数据列、密集但可展开的行 |
| 字体 | 系统中文；数值等宽；少量工程编号 | 系统文字样式优先，最少额外样式 | 标题简洁、数字对齐，长文仍用比例字体 |
| 工厂页 | 中性画布、清晰端口、适度状态条、非模态属性面板 | 原生工具按钮与紧凑底部属性区，沿用现有手势 | 多指标摘要；iPad 可同时看画布、属性、统计 |
| 配方页 | 搜索与数量为紧凑控制区，结果为节点工作区 | 原生搜索、Stepper / 数量输入、标准详情 | 目标与总览紧邻，图与可读明细互补 |
| 蓝图页 | 地图选择 + 作者搜索，紧凑方案行 | 标准搜索与分组列表 | 地图、作者、数量、说明按列/行层级对齐 |
| 优点 | 游戏关联鲜明，适合本 App，兼顾密度 | 上手快，无障碍与适配成本较低 | 复杂数值比较效率好，iPad 优势明显 |
| 主要风险 | 容易又回到黄框、微型标签和装饰线堆砌 | 容易缺少产品辨识度 | iPhone 容易拥挤，必须随宽度和字号重排 |

### 同一个工厂任务在三种方向中的差异

任务：打开画布 → 选择建筑 → 判断缺料原因 → 修改配方 → 查看产出。

- **A**：地图与当前工具在顶部；底部工具坞；选中建筑出现非模态检查面板，先展示“状态 / 实际产出 / 缺料”，再进入可搜索配方选择器。画布仍能操作。
- **B**：使用系统工具栏和常规层级，更多依赖熟悉的原生列表和按钮；选中后在底部内嵌属性区查看，避免用模态弹窗阻止画布交互。
- **C**：先看到“电力余量 / 异常建筑 / 产线”摘要；属性面板按需求、到货、实际产出排列。只展示已有模拟输出，不新增推算算法。iPhone 的数据列会在大字号改为上下排列。

### 推荐组合及边界

推荐 **A 的视觉语言 + B 的导航与原生控件 + C 的数据排版**。它们采用同一套 Token 和组件规则，不在三个模块各用一套主题。

代表页建议选择 **基建规划 `FactoryLayoutView`**：它能同时验证工业气质、画布密度、工具入口、建筑状态、属性面板和产能数据。Phase 3 先保持当前进入路径及 ViewModel 生命周期，只改变视图组织；确认实际截图后再推进全 App 导航调整。

不新增虚假在线状态、运营图表、推荐算法、远程同步、游戏账号登录或未实现功能。不导入第三方 UI 库，不直接复制参考作品的图片、字体或资产。

## 5. 需确认的设计选择

- 主方向：A / B / C，或推荐组合。
- 全局导航：建议保留首页作为“工作台”，将配方、蓝图、基建作为平级入口；设置从工作台齿轮进入。
- 代表页：建议先改基建规划，再确认视觉方向；此后逐页实施。
